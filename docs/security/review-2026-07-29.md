# Security and Resource-Safety Review — 2026-07-29

## Verdict

**Conditional Go for code; No-Go for publishing the existing artifact.**

The product targets have no network client, analytics SDK, account boundary, or remote
data flow. The reviewed local boundaries are pasteboard capture, pinned archive import,
encrypted history/Keychain migration, iPhone Application Support, Accessibility paste,
and release credentials.

## Resolved findings

- Manifest commits now follow blob write → atomic manifest → best-effort cleanup.
- Lazy image references avoid startup decryption and unchanged blob rewrites.
- Save generations prevent an older cancelled task from overwriting newer history.
- New AES keys are Keychain-only; legacy migration verifies read-back before moving the
  old key to a downgrade backup.
- Blob filenames are basename-validated on macOS and iPhone.
- Clipboard/import item, byte, image, text, and file counts are bounded.
- Imported payload hashes, kinds, previews, and image metadata are rebuilt from payloads.
- iPhone files use complete-until-first-authentication data protection.
- Persistence and user-operation failures are visible.
- Release secrets are external inputs; the release script requires Developer ID,
  notarization, stapling, Gatekeeper assessment, archive revalidation, and checksum.

## Remaining findings

  publish it as evidence for this code. Run the credentialed release workflow and record
  accepted notarization plus `spctl` output.
- **Important:** the legacy key backup is intentionally retained for downgrade recovery.
- **Important:** moved file bookmarks resolve, but stale bookmark refresh is not written
  back yet.
- **Important:** real cross-application Accessibility paste automation remains limited to
  manual verification.

## Not assessed
