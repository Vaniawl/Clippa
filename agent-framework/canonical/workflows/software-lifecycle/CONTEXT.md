# Route one outcome across applicable product stages

Purpose: route one outcome across applicable product stages. This is the local context boundary;
[WORKFLOW.md](WORKFLOW.md) remains authoritative for detailed steps and gates.

## Inputs

| Source | Scope / why |
| --- | --- |
| User request or saved task contract | Approved outcome and criteria; PROJECT/vision/scope only when product context matters; existing artifacts for applicable stages. |
| [Workflow](WORKFLOW.md) | Entry/exit criteria and only applicable stages |
| [Operating instructions](../../operating-instructions.md) | Mandatory execution/authority rules; read once per confirmed context |

## Process

Choose the applicable stages in WORKFLOW.md; read only their listed inputs; complete the bounded work and applicable review/checks; hand over.

Load only the references required by the current step. Retain confirmed context;
when a dependency is unavailable, record the specific gap instead of inventing evidence.

## Outputs

Only stage artifacts required by the approved outcome, at existing code/docs locations; task evidence and handover link to them.

## Human and independent gates

Stage gates apply when relevant; no mandatory whole-lifecycle or role checklist. Scope expansion and required independent review retain their existing gates.
Advice stays in conversation unless saving is requested; existing role ownership applies.
