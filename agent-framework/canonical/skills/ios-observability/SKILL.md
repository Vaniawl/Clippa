# iOS observability

Identify the failing user task, build/device/OS and available raw diagnostics. Use
[diagnostics.md](references/diagnostics.md) for performance, incident or field evidence.
Do not install analytics or monitoring automatically. Logs and support exports need data
minimization; unavailable field data is UNKNOWN, not a clean bill of health.

Return a reproduction, measured baseline/result, causal evidence and bounded next action.
Separate source hypotheses, local measurements and field observations. Product fixes remain
within the active role's ownership; support roles deliver sanitized triage and escalation.

## Research when needed

Use supplied/local primary sources or actually available web/docs tools permitted by the role
and task. If the active role lacks the `web` tool or access and local evidence is insufficient,
request a deep-researcher task via the orchestrator when available, or mark the claim UNKNOWN
and continue independent work. Do not infer access from a catalog or simulate source verification.
